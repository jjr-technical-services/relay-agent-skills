# Open-ended coding

## Build the codebook

1. Read a sample (for example, 20 to 30 responses, or all if fewer) without coding, noting recurring ideas.
2. Draft codes. Each code gets:

| Field | Content |
|---|---|
| Code | Short label, for example "Wanted more time" |
| Definition | What the code means in one sentence |
| Include | What counts, with edge cases |
| Exclude | Similar ideas that belong elsewhere |
| Example | A short paraphrase, never a verbatim identifying quote |

3. Aim for 5 to 12 codes. Add "Other" for responses that fit nowhere, and revise the codebook if "Other" grows large.
4. Code every response; a response can carry more than one code.
5. Count: number of respondents mentioning each code, and share of those who answered the question (not of all respondents). Say which denominator is used.

## Checking agreement

When results will be reported externally or drive a decision, have a second person code a random subset (for example, 20% or at least 20 responses) using the codebook.

- Percent agreement = responses where both coders applied the same code / responses coded by both.
- Cohen's kappa adjusts for chance agreement: kappa = (po - pe) / (1 - pe), where po is observed agreement and pe is the agreement expected by chance from each coder's code frequencies. Compute per code (applied or not applied) when responses can have several codes.
- Discuss disagreements and refine definitions; the goal is a codebook others can apply consistently.

Illustrative (hypothetical): two coders review 50 responses for one code. Both apply it to 20, both leave it off 20, and they disagree on 10. po = 40 / 50 = 0.80. Coder A applied it to 25, coder B to 25. pe = (25/50 x 25/50) + (25/50 x 25/50) = 0.25 + 0.25 = 0.50. kappa = (0.80 - 0.50) / (1 - 0.50) = 0.60.

## Quoting

- Paraphrase by default. Use a short verbatim phrase only if it cannot identify the person (no names, places, roles, unique events) and the survey said comments might be shared.
- Do not quote responses from groups below the suppression threshold; the group label plus the quote can identify someone.
- Do not quote responses that describe personal distress, health, or crisis, even anonymized.

## Responses that need a human

If a response suggests someone may be at risk, discloses harm, or asks for help, stop analyzing it. Tell the user it needs review under the organization's safeguarding or response procedure, and exclude it from the report text. Do not assess the response yourself.

## Reporting themes

Order codes by count. For each, give the count and share, a one-sentence description, and a paraphrased example. Note which themes differ by group only where groups meet the suppression threshold. Themes describe what respondents said, not how common a view is among everyone invited.
