# Tracking, gift processing and post-campaign review

## Tracking codes

Decide codes before launch and put them in the CRM and donation platform first.

- **Appeal code:** one per campaign, for example `FY27-YE` for a fiscal-year-27 year-end campaign (illustrative format).
- **Source or package code:** one per segment and channel combination, for example `FY27-YE-LAPSED-EMAIL2`.
- **Link tagging:** add URL parameters to every link so web analytics can attribute visits and gifts: `utm_source` (where the link lives, such as the email list name), `utm_medium` (email, social, sms, print), `utm_campaign` (the appeal code), and optionally `utm_content` (which message or button). Keep values lowercase and consistent.
- **Printed pieces:** a reply device code or a short vanity link per segment.
- **Unattributed gifts:** code them to the appeal with source "unsolicited" rather than leaving the field blank.

Record the code mapping in one table the gift processor and analyst both use.

## Gift processing and acknowledgment handoff

| Step | Standard to set | Notes |
|---|---|---|
| Online gift received | Automated confirmation immediately | Platform confirmation meets the need for a prompt thank-you but check it carries the required receipt content |
| Checks and mailed gifts | Logged and deposited on a set schedule | Two-person handling for cash and checks where staff allow |
| CRM entry | Within the organization's standard | Appeal and source codes, fund or restriction, tribute details, match eligibility |
| Personal acknowledgment | Per the acknowledgment standard | Content and signer follow `plan-donor-stewardship` |
| Tribute notification | Within the organization's standard | To the designated person; amount only with donor consent |
| Employee match follow-up | Before the company's deadline | Track submitted, confirmed, paid |
| Match progress | Updated from actual eligible gifts | Report to matcher as agreed |
| Restricted gifts | Coded to the restricted fund | Finance reconciles monthly |
| Event or benefit payments over $75 | Quid pro quo disclosure with good-faith estimate | Accountant confirms values |

Plan for peak volume: year-end and giving day concentrate gifts into a few days. Name backup processors and signers.

## Post-campaign review

Plan the review before launch so the data is captured. Hold it within a few weeks of close while details are fresh, and again when second-gift results are known.

Measures, with formulas:

| Measure | Formula |
|---|---|
| Response rate by segment | donors in segment ÷ people asked in segment |
| Average gift by segment | revenue in segment ÷ gifts in segment |
| Revenue versus build-up | actual revenue ÷ base-case expected revenue, per segment |
| Gross revenue | all campaign gifts including match and leadership |
| Net revenue | gross revenue − direct campaign costs |
| Cost per dollar raised | direct campaign costs ÷ gross revenue |
| New donors acquired | donors whose first-ever gift carries this appeal code |
| Recurring sign-ups | new recurring commitments with this appeal code |
| Peer-to-peer activation | fundraisers with at least one gift ÷ fundraisers registered |
| Match earned | min(cap, ratio × eligible gifts) |
| Second-gift conversion (later) | new donors from this campaign who give again within the chosen window ÷ new donors from this campaign |

Review questions:

1. Which segment assumptions held, which did not, and by how much?
2. Which channel and message combinations produced gifts, based on source codes rather than impressions?
3. Were any ethics rules bent under pressure? What will prevent that next time?
4. Did acknowledgment meet its time standard at peak?
5. What will be updated in the goal build-up for next year?

Store the review with the segment table so next year's goal starts from these actuals.
